# Backup, Restore & DR (Topic 40)

Drill (`POST /api/v1/sd/lab/backup`, disposable DB, real migration runner, audit verifier, inventory ledger): seed 2 orgs (40 deliveries + 40 audit events each) → online backup while a writer thread keeps writing → delete source DB → restore → re-run migrations (no-op) → validate.
Results (5 runs, all invariants held every run): audit chains valid (both orgs); stock = ledger sum per org; 0 cross-tenant rows; 0 FK violations; `integrity_check ok`; tamper of a restored audit row is detected. Timings (tiny DB, one machine): backup ≈5.7 ms, restore+validate ≈7.2 ms; events written after the backup instant were lost (1–2 per run) — the measured RPO of an ad-hoc backup.
NOT executed/implemented: application restart under load, plan-version checksum and delivery-receipt integrity checks on restored data (only audit/inventory/tenant/FK checks run — add next), scheduled backups, encryption/immutability of backups, retention, PostgreSQL PITR (platform-managed/PLANNED). **No production RTO/RPO is claimed.** Proposed (unverified) goals to validate: RPO ≤ 15 min, RTO ≤ 4 h for a demo→pilot NGO tool; must be confirmed with NGO stakeholders and a real restore at real size.
