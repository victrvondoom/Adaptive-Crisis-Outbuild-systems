# Observability (Topic 36)

Implemented (`app/telemetry.py`): W3C-traceparent-compatible parse/generate (invalid → fresh trace, never an error); contextvars propagate trace/span; spans: `http.request`, `db.query` (verb only), `agent.run_action` (ids only), `optimizer.solve_allocation`; response headers `X-Request-ID`, `X-Trace-ID`; JSON logs carry request_id/trace_id; deterministic head sampling `TRACE_SAMPLE_RATE`; bounded ring buffers; redaction by key (name, phone, address, email, token, authorization, password, secret, signature, note, source_text) and by pattern (emails, phone numbers); logging filter; instrumentation failures counted, never raised. Endpoints (AUDIT_READ): `/api/v1/sd/telemetry`, `/trace/{id}`, `/slo`.
Measured: ≈3.4 µs/span overhead (20k no-op spans); trace demo: 4 spans, correct parent chain gateway→{db, agent→optimizer}.
Not implemented / NOT_MEASURED: OpenTelemetry SDK/exporter (data model is compatible; evaluation: add `opentelemetry-sdk` only when a collector exists), Prometheus/Grafana, queue lag, model latency (no LLM), provider health, recovery time dashboards. Telemetry is in-memory and resets on restart. Organization-safe ids: org_id is not placed in span attributes; route templates replace ids.
